# Wireframing

## Objective
Translate user tasks and UX research into clear screen structures and interaction flows before polished visual treatment.

## Procedure
1. Review discovery, UI/UX research, and the existing design system.
2. Identify the screen inventory and primary user journey.
3. Define information hierarchy, navigation, grouping, and primary/secondary actions.
4. Sketch low-fidelity layouts for relevant viewport sizes.
5. Include empty, loading, error, success, disabled, and permission states.
6. Specify keyboard order, focus destinations, accessible names, and validation behavior.
7. Map screen transitions and note where data or confirmation is required.
8. Review wireframes against the original user tasks and constraints.

## Deliverable
Wireframes with screen/viewport labels, content hierarchy, actions, state variations, interaction flow, responsive adaptations, and unresolved questions.

## Guardrails
- Keep wireframes low fidelity until structure is validated.
- Do not omit relevant error and empty states.
- Do not create controls without describing their behavior.
- Do not add screens or steps that do not serve a user task or constraint.
